# 0069. `ИнфоТипа` — плоское детерминированное значение

- Статус: принято
- Версия: v0.180
- Спецификация: §4.5; §12.5, п. 7

## Решение

`компил_инфо(Т)` возвращает `ИнфоТипа` — обычный `переч` прелюдии из значений: примитивы со знаковостью и битностью, `Структура` и `Набор` с именем, размером, выравниванием и срезом `ИнфоПоля` (имя, тип, смещение), `Перечисление` со срезом `ИнфоВарианта` (имя, номер, нагрузка), ссылка, указатель, срез, массив, короткий вектор, опция, кортеж, функция, замыкание, `дин` и типаж. Вложенные типы — значения `тип`, поля и варианты идут в порядке объявления, имена — в написании объявления. Размеры и смещения считаются по правилам раскладки §4.5 для цели `компил_цель()`; эти правила дописаны: тег `переч` в начале, общая нагрузка после него с самым строгим выравниванием, без тега — `?` от указателеподобных типов, `Вектор` — по степени двойки, элемент `набор` — по колонкам. Имена вариантов выбраны так, чтобы не совпасть с типами прелюдии: `МассивФикс`, а не `Массив`, `КороткийВектор`, а не `Вектор`.

## Причина

Рефлексия через `цикл компил` пишет `текст.формат` и сериализацию, и её результат не должен зависеть от того, какой компилятор её вычислил — нынешний на C++ или будущий на Сплаве. Внутренние идентификаторы, адреса объявлений и порядок хеш-таблиц в значении сделали бы его разным от сборки к сборке.

## Отвергнутые варианты

- Непрозрачный дескриптор с запросами `имяПоля(т, номер)`: результат зависит от реализации запросов, а `выбор` по виду типа становится цепочкой вызовов.
- Порядок полей по раскладке, а не по объявлению: у `[Плотный]` он зависел бы от алгоритма упаковки; порядок объявления плюс смещение отдают оба факта.
- `ИнфоТипа` в отдельном модуле: `компил_инфо` из прелюдии вернула бы тип, которого без подключения нет.

## Плата

Раскладка зафиксирована только для 64-битных целей порта; новая цель с другим размером слова потребует правила в §4.5. Доступа к полю значения по имени из `ИнфоПоля` пока нет — сериализация пишется через `выбор` по имени.
