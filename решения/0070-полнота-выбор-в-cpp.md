# 0070. Полнота `выбор` в C++ — алгоритм полезности модели

- Статус: принято
- Версия: v0.180
- Спецификация: §3.4; §11.3; §14.3, п. 2

## Решение

С0301 и С0302 проверяет `компилятор/sema` (coverage.cpp) тем же алгоритмом, что и прототип модели: матрица образцов, конструкторы из типа (`?Т` — `Есть` и `Ничего`, `бул` — `да` и `нет`, кортеж, варианты `переч` с нагрузкой, `структ` с полями — один конструктор), развёртка `или`, свидетель непокрытого случая с первого непокрытого конструктора, ветви с `если` не покрывают. Глубина разбора ограничена 12 уровнями, как в модели. Если проверка типов не вывела тип разбираемого значения, компилятор не сообщает С0301 по этому столбцу и не считает образцы равными по пути, если у них есть поля. Злые примеры 01 и 02 типов сверяются и с компилятором, и с моделью.

## Причина

Перенос правил памяти начинается с правил уровня типов (запись 0068); один алгоритм в двух реализациях даёт одинаковые свидетели, и модель остаётся оракулом построчно. Перенос нашёл ошибку модели: безымянные аргументы образца попадали в первую безымянную позицию нагрузки, потому что метка `None` находилась среди меток `None`; теперь они идут по порядку.

## Отвергнутые варианты

- Перебор значений вместо матрицы: экспоненциален на кортежах и вложенных `переч`.
- Пересечения диапазонов целых для С0302: модель сравнивает литералы по написанию, расхождение с оракулом было бы ошибкой.
- Сообщать С0301 при невыведенном типе: постепенная проверка дала бы ложные ошибки, пока вывод типов в обобщённом коде не готов.

## Плата

Пока тип не выведен, компилятор пропускает часть неполных `выбор`, которые находит модель; разрыв закрывается вместе с полным выводом типов.
