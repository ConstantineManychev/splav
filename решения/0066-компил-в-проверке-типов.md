# 0066. Проверка типов исполняет `компил` через интерпретатор

- Статус: принято
- Версия: v0.180
- Спецификация: §12.5; §14.3, п. 2

## Решение

Проверка типов получает исполнитель `компил` — интерфейс `ComptimeEvaluator` в `sema`, который реализует интерпретатор и подключает драйвер. Тип вида `Пара(ц32, стр)`, где `Пара` — функция, возвращающая `тип`, проверка вычисляет: выводит типы аргументов, и если все известны, исполняет функцию и получает объявление с параметрами-привязками — поля и варианты такого типа ей известны. Псевдоним `конст Век3 = Вектор(в32, 3)` разрешается по выражению константы. Интерпретатор проверки делит с ней базу объявлений, поэтому объявления и функции — одни и те же объекты. Прототип модели памяти разворачивает функцию, тело которой — один `возврат структ { … }` или `переч { … }`, в обобщённое объявление: это сахар §12.1 в обратную сторону.

## Причина

По §12.5 обобщённый тип — функция времени компиляции, и без её исполнения проверка не знает полей `Пара(ц32, стр)` и пропускает ошибки в таком коде. Интерфейс в `sema` держит зависимость в одну сторону: `interp` зависит от `sema`, а не наоборот.

## Отвергнутые варианты

- Свой вычислитель типов в проверке: второй интерпретатор `компил` со своими расхождениями.
- Слить `sema` и `interp` в одну библиотеку: проверка имён и типов потянула бы рантайм-часть интерпретатора.
- В модели исполнять произвольные функции типов: прототип модели проверяет память, а не `компил`; развёртка сахара покрывает объявления, которые пишут на практике.

## Плата

Тип с неизвестными аргументами — например, внутри обобщённой функции до подстановки — остаётся неизвестным. Паника в `компил` при проверке пока не становится ошибкой компиляции, бюджета шагов нет (§12.5, п. 5). Модель не понимает функции типов сложнее одного `возврат`.
