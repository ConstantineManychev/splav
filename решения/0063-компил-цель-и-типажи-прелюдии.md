# 0063. `компил_цель()` вместо голого `цель`; типажи операторов в прелюдии

- Статус: принято
- Версия: v0.180
- Спецификация: §2.6; §10.1; §12.5, п. 2; §12.6

## Решение

Цель сборки описывает встроенная функция времени компиляции `компил_цель()`: она возвращает `Цель{ ос, архитектура }` с вариантами `Ос.Linux`, `Ос.Windows`, `Ос.MacOS` и `Архитектура.X86_64`, `Архитектура.AArch64`. Пример §12.5 пишет `компил если компил_цель().ос == Ос.Windows`. Прелюдия получает все типажи операторов, которые называет §12.6: `Сравнение` с перечислением `Порядок` (`Меньше`, `Равно`, `Больше`), `Деление`, `Остаток`, `Отрицание` и `Индексация`.

## Причина

Пример §12.5 обращался к `цель`, которого нет ни в языке, ни в ядре: разрешение имён его не находило. Встроенные функции времени компиляции по §2.6 пишутся через `_` и не пересекаются с пользовательскими именами, а `цель` — обычное слово: корпус ecs называет так привязку в образце `Урон(цель, сколько)`. Типажи §12.6 были названы, но не объявлены, поэтому `реализ Сравнение для Точка` давал С0201.

## Отвергнутые варианты

- Встроенное значение `цель` без `_`: заняло бы частое слово и нарушило бы правило §2.6.
- Модуль `ядро.цель` с подключением: ради одного значения времени компиляции, которое нужно и самой прелюдии.
- Строки вместо перечислений (`"windows"`): опечатка не была бы ошибкой компиляции.

## Плата

`Ос` и `Архитектура` перечисляют только платформы порта (§6.6); новая цель — новый вариант в прелюдии. ГПУ-цели гибридных функций сюда не входят: их выбирает исполнитель (§7.2).
